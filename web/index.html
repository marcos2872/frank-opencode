frank-opencode
Como funciona Instalar Configurar Limites GitHub

Seus modelos do opencode respondem como a API da Anthropic.

O frank-opencode é um gateway local. Ele recebe a Messages API que o Claude Code e o Claude Desktop falam, resolve o modelo no catálogo do OpenCode v2, traduz cada requisição para o protocolo do provedor — passthrough Anthropic, OpenAI Chat Completions ou Responses API — e traduz a resposta de volta, streaming incluído. Escuta só em 127.0.0.1 e nunca fala com a Anthropic: o upstream é o backend Go/Console do OpenCode, autenticado com o login que você já tem.

Instalar em três comandos Ver a tradução

A tradução, campo a campo

Traduzir API não é só renomear chaves. As duas famílias discordam sobre onde mora o papel da mensagem, como o streaming é fatiado e o que significa uma chamada de ferramenta. O frank resolve as três — e escolhe o protocolo certo por modelo: pacotes Anthropic fazem passthrough de bytes para {baseURL}/messages, pacotes OpenAI vão para /chat/completions, linhas Go GPT/Grok/Muse vão para /responses.

01 · entra

O cliente aponta para o gateway local

Claude Code via ANTHROPIC_BASE_URL=http://127.0.0.1:3737; Claude Desktop via gateway inference apontando para a mesma base. Nenhum patch, nenhum binário trocado.

02 · resolve

O frank resolve o modelo no catálogo

Alias do gateway → provider/model → id simples. A ordem é essa; ids ambíguos ordenam por nome qualificado, com aviso. Sufixo de janela [1m] é removido ao resolver. Variantes #variant são validadas contra o catálogo — label desconhecido devolve 404 listando as disponíveis.

03 · traduz

Traduz para o protocolo do modelo e encaminha

Blocos de conteúdo, ferramentas e histórico são reconstruídos no formato do upstream. O Bearer vem do SQLite do OpenCode (tabela credential, lida em modo read-only — nunca auth.json como fonte) e o forward sempre envia x-opencode-session. Modelos free-tier opencode/* usam a chave pública de settings.apiKey e dão 403 fora do OpenCode — por isso ficam ocultos por padrão.

04 · volta

A resposta é remontada no dialeto da Anthropic

Inclusive o streaming: os deltas do provedor são reemitidos como content_block_delta, na ordem e no formato que o cliente espera — com ping injetado durante o silêncio do upstream para o watchdog não travar. Erros do upstream viram o formato de erro Anthropic.

Instalar

O frank não pede suas credenciais de novo. Ele herda o login que o opencode já tem — lido do banco SQLite, em memória, nunca logado.

passo 1 · pré-requisito, uma vez só

Tenha o OpenCode v2 autenticado

Se opencode auth login já mostra seus provedores, pule para o passo 2. O frank lê essa mesma credencial no SQLite (caminho via opencode debug paths db).

shell
$ opencode auth login
passo 2 · instale o binário

Baixe da última release

Ou compile localmente com cargo install --path ..

shell
$ URL=$(gh release view --repo marcos2872/frank-opencode --json assets --jq '.assets[] | select(.name=="frank-opencode-linux-x86_64") | .url')
$ curl -L "$URL" -o /tmp/frank-opencode
$ install -m 0755 /tmp/frank-opencode ~/.local/bin/frank-opencode
$ frank-opencode --version
passo 3 · suba o gateway

Rode como daemon em background

O catálogo é lido no boot em background (com retry); /health fica starting até o primeiro load.

shell
$ frank-opencode --enable
$ frank-opencode --status
$ curl -s http://127.0.0.1:3737/health

Porta custom: frank-opencode --enable --port 3740. Com ele rodando, trocar de porta exige --disable antes. Logs em ~/.local/share/frank-opencode/frank.log. Prévia do catálogo sem subir: frank-opencode --refresh.

passo 4 · escolha o modelo no cliente

Não há comando use — selecione no picker

Os modelos aparecem em GET /v1/models como aliases claude-<provider>-<model>. No Claude Code, escolha com /model (exige CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1). Aliases manuais e [disabled] vão no config.toml — ver Configurar.

shell
$ curl -s http://127.0.0.1:3737/v1/models | jq -r '.data[].id' | sort
shell — sessão atual 
export ANTHROPIC_BASE_URL=http://127.0.0.1:3737
export ANTHROPIC_AUTH_TOKEN=dummy
export CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1
claude
~/.claude/settings.json — persistente (escopo do usuário) 
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:3737",
    "ANTHROPIC_AUTH_TOKEN": "dummy",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1"
  }
}

ANTHROPIC_AUTH_TOKEN aqui é a credencial do gateway (auth_token do config.toml), não uma chave da Anthropic — por padrão o gateway aceita qualquer valor em loopback, então dummy basta. Quando auth_token está setado, o valor precisa ser igual. A credencial do provedor vem do SQLite do OpenCode; o gateway nunca fala com a API da Anthropic.

Subagentes (Explore, general-purpose) podem escolher um id de snapshot da Anthropic que o OpenCode não oferece. Fixe com um id exato de /v1/models: CLAUDE_CODE_SUBAGENT_MODEL="SEU_ID_EXATO" + CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1, incluindo o sufixo [1m] quando ele aparecer.

shell — permissões exigidas + reinício 
$ frank-opencode --enable # ex.: http://127.0.0.1:3737
$ sudo chown root:root /etc/claude-desktop/managed-settings.json
$ sudo chmod 0644 /etc/claude-desktop/managed-settings.json # 0600 dá EACCES; o app lê como seu usuário
$ sudo chmod 0755 /etc/claude-desktop

Base URL sem sufixo /v1 (o app anexa /v1/messages sozinho) e com 127.0.0.1, não localhost. inferenceGatewayApiKey = valor do auth_token do gateway (ou qualquer placeholder se vazio). Feche o Desktop por completo e reabra — a config só é lida no boot; na tela de login aparece Continue with Gateway (saia da conta Anthropic se já logado).

Builds oficiais Mac/Windows: Help → Troubleshooting → Enable Developer Mode, depois Developer → Configure Third-Party Inference com os mesmos valores (provider Gateway, Static API key, scheme Bearer). Para listar todos os modelos no picker, ative desktop_aliases = true (ver Configurar) e reinicie gateway + Desktop.

Configurar

Arquivo em ~/.config/frank-opencode/config.toml (exemplo completo em config.example.toml). Overrides: --port / FRANK_PORT, --config / FRANK_CONFIG, FRANK_AUTH_TOKEN (não-vazio sobrescreve o arquivo). O config é lido no boot — trocar exige reiniciar (--disable + --enable). Arquivo inválido é erro fatal, não default silencioso.

modelos

Automático, manual e janela

Cada modelo habilitado do OpenCode ganha um alias claude-<provider>-<model> (o prefixo claude- é obrigatório para o discovery). Linhas com mesmo provider/model mas id distinto (ex. opus-4.8 vs opus-4.8-fast) ganham aliases distintos, com anthropic-beta/speed do catálogo repassados.

Janelas < 1M e o aviso "X" isn't described by this version's model catalog não se resolvem no gateway: fixe no Claude Code com modelOverrides (behavesAs / inputWindowHint) ou, em último caso, CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1.

variantes

Sufixo #variant, traduzido por protocolo

Chat Completions: reasoning_effort (labels fora do enum, como xhigh/max, saturam para high; none remove o parâmetro). Responses API: objeto reasoning + include declarados. Passthrough Anthropic: thinking (adaptive com display: summarized, ou disabled para none). Variante sem representação segura no Messages API retorna 400, nunca silêncio.

Regra de ouro: catálogo é lido uma vez no boot (com até 6 tentativas e backoff 2s → 16s enquanto vier vazio). Sem refresh automático — modelo novo/removido ou opencode auth novo pede frank-opencode --disable && frank-opencode --enable. --refresh só pré-visualiza.

O que o proxy não faz

Um tradutor honesto diz onde não alcança. Se algo aqui for um problema para você, é melhor saber antes de instalar.

Nem todo recurso da Messages API tem equivalente

Ferramentas que o provedor não implementa não são inventadas. Recursos exclusivos da Anthropic — como trechos com cache de prompt e busca na web hospedada — só funcionam quando o provedor de destino oferece algo equivalente.

Na dúvida, o proxy prefere falhar com um erro claro (sempre no formato {"type":"error","error":{...}}) a devolver uma resposta silenciosamente diferente do que foi pedido.

É um proxy local, não um serviço hospedado

O frank escuta só em 127.0.0.1, abre o DB em read-only e mantém segredos só em memória (nunca logados). Arquivos de estado (frank.pid, frank.port, frank.session, frank.log) são criados 0600. Suas chaves e conversas passam por ele, mas ficam entre você e o provedor — nada é enviado para terceiros.

O catálogo congela no boot

Sem refresh periódico: /health fica starting até o primeiro load e degraded se as tentativas esgotarem com 0 modelos. models: 0 logo após o boot costuma ser o serviço do OpenCode ainda aquecendo (opencode service status + reinicie o gateway). frank.log é só-append — trunque de vez em quando.

A qualidade da resposta é do modelo, não da tradução

O proxy garante que a requisição chegue bem formada e que a resposta volte no formato esperado. Ele não equaliza capacidades: um modelo mais fraco em uso de ferramentas continuará mais fraco, mesmo falando fluentemente o dialeto da Anthropic.
